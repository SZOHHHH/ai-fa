## 2. 四类实体模板

### 2.1 论文 Paper（frontmatter + 七节）


7. **读前须知**（需要先懂哪些 〔数学概念〕）

3. **核心公式**（链到公式页，可多个）

5. **变体与演进**（表：变体 | 相比本概念改了什么 | 代表论文）
6. **对比表**（与相邻算法概念横向对比，如 FM vs DDPM vs GAN）

5. **数学概念分解**（链到概念页）

## 3. 边语义（全库统一记法）

### 3.0 网络架构：一张数据图，多张视图

**结论：四种实体放在同一张图（单库单链路）；"论文网络""公式网络"的分离靠视图过滤实现，不做物理拆分。**

- **数据层（唯一）**：所有实体同库，所有 `〔链接〕` 处于同一链路空间；允许的边由下方关系矩阵限定
- **视图层（多张，按需切换）**：
  - **论文网络** = Graph 过滤器只显示 `10-Papers/`
  - **公式网络** = Graph 过滤器只显示 `30-Formulas/` + `40-Concepts/`
  - **全网络** = 默认 Graph，按文件夹分组四色着色（库内预设分组）
  - **Canvas 族谱**（B7 批）= 带边语义标签的精编视图
  - **Bases** = 每类实体的表格/数据库视图

**为什么不拆库**：核心用户旅程是跨类型的（论文 → 公式 → 数学概念），物理拆分会切断这条链路；Obsidian 的 Graph 文件夹过滤器让"分开看"零成本。未来导出 Web 应用时，同样是"一张图数据库 + 多个视图"的架构，数据模型不用重构。

**实体关系矩阵（允许的边及语义，矩阵外不允许建边）**：

| 从 \ 到 | Paper | Algorithm | Formula | Concept |
|---|---|---|---|---|
| **Paper** | 发展关系（§3.2 动词集） | 提出/采用算法 | 使用公式（核心公式节） | 前置知识（读前须知节） |
| **Algorithm** | 本命论文群 | 变体/对比/演进 | 核心公式归属 | 分解 |
| **Formula** | 出处 | 所属算法 | §3.1 四种数学边 | 分解 |
| **Concept** | 出现于 | — | 出现于 | 相关概念 |

注：矩阵保证双向一致——算法页列本命论文群、公式页列出处，链接互指。

### 3.1 公式间/概念间的 4 种边

| 边       | 记法                                                                                      | 示例                               |
| ------- | --------------------------------------------------------------------------------------- | -------------------------------- |
| 等价变形    | `≡ 等价于 [[…]]`                                                                           | ε-预测 ≡ v-预测（线性等价）                |
| 泛化/特化   | `⊃ 泛化于 [[…]]` / `⊂ 特化于 [[…]]`                                                           | score-SDE ⊃ 泛化于 DDPM             |
| 推导链     | `→ 由 [[…]] 推导`                                                                          | DPO → 由 RLHF 目标闭式求解奖励推导          |
| LOSS 分类 | `#loss/regression` `#loss/adversarial` `#loss/contrastive` `#loss/expectation-of-ratio` | DPO = #loss/expectation-of-ratio |

规则：**每条边必须带一句话说明**（Obsidian 链接本身无标签，语义写在行内）。
公式页 frontmatter 的 `loss_type` 字段与 LOSS 分类边同步。

### 3.2 论文间的边（单句公式化）

固定动词集合，避免随意措辞：
- `改进了 [[…]]：<具体改进>`
- `简化了 [[…]]：<简化了什么>`
- `扩展了 [[…]]：<扩展到什么>`
- `组合了 [[…]] 与 [[…]]：<组合方式>`
- `对比了 [[…]]：<差异结论>`
- `奠基了 [[…]]`（仅用于事后视角）

## 4. 质量红线（写入前自检）

1. frontmatter 齐全、`type` 正确
2. 公式只用 [[00-Meta/记号规范]] 标准记号，变体进对照表
3. 所有 `〔链接〕` 指向的文件**必须已存在或本批内创建**（不允许红链）
4. 每条边带一句话语义
5. 面向读者：数学薄弱但想入行的学生——直觉解释不可省略
